# NES ROM Analysis Workbench

## Purpose

Extend Professional Editor from text-slot editing into a local-first, read-only analysis workbench for NES ROMs. This complements the existing editor and must never silently patch, normalize, or overwrite an input ROM.

## Analysis domains

1. **Container and mapper** — validate iNES/NES 2.0 header, declared PRG/CHR sizes, optional trainer, mirroring, battery, mapper/submapper, and truncation/trailing-data warnings.
2. **Graphics and assets** — decode raw CHR 2bpp 8x8 tiles, export tile sheets and tile metadata, and later infer sprite groupings, animation frames, background patterns, palettes, nametables, attribute tables, and PPU usage. Raw tiles are evidence; a tile is not automatically a complete sprite.
3. **Text and tables** — locate printable strings, accept optional game-specific .tbl files, and annotate likely menus, dialogue, item names, level labels, and configuration tables.
4. **Code and control flow** — mapper-aware 6502/2A03 disassembly; vector and bank mapping; code/data classification; candidate functions, branches, calls, indirect jumps, and cross-references. Keep ambiguous bytes classified as unknown rather than asserting all PRG is executable code.
5. **Gameplay and settings** — discover candidates for input polling, movement, collision, enemy AI, level progression, score/lives/health/timers, difficulty, item drops, save state, and menu configuration. These are hypotheses until supported by code evidence or execution traces.
6. **Dynamic validation** — future optional emulator integration for frame-by-frame input/state traces, memory watchpoints, screenshots, and reproducible test scenarios.

## Current first step

The analysis/nes_inspect.py tool is a dependency-free, read-only first-pass inspector. It validates common iNES/NES 2.0 size metadata, emits JSON, reports header/region details, scans basic printable ASCII candidates, records PRG vectors as raw file offsets when meaningful, and exports a grayscale PGM sheet from CHR-ROM tiles. It does not claim to identify complete sprites, decode arbitrary game text, disassemble code, or infer gameplay rules.

## Suggested outputs

Each ROM gets its own output directory containing:
- report.json — machine-readable header, region offsets, warnings, vectors, and first-pass findings.
- chr-tiles.pgm — raw CHR-ROM tile sheet, if CHR-ROM exists.
- README.md — human-readable findings and limitations.

Never put ROM images, extracted copyrighted assets, screenshots, or derived game data into Git. Test fixtures must be synthetic and generated by project tooling. Local reports and extracted assets belong outside the repository or in ignored output folders.

## Quality requirements

- No writes to source ROMs.
- Validate bounds before reading regions and cap memory use for malformed input.
- Keep offsets explicit: file offset, PRG-relative offset, and CPU address are different concepts.
- Mark inferred data with confidence and evidence; never present heuristics as facts.
- Support batches while isolating failures per file.
- Add synthetic tests for iNES, NES 2.0 size encodings, trainer offsets, CHR-RAM, truncated files, invalid magic, and tile-plane decoding.
- Keep language-specific editor implementations and their shared text-edit grammar unchanged.
